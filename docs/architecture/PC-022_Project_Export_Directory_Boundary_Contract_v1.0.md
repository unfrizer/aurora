## Exact public API

Add precisely one method to the existing `ProjectRepository` class:

```python
def export_directory(self, project_id: str) -> Path: ...
```

It validates a canonical project ID through P1's existing rules, locates
exactly one existing project, loads its metadata/state to verify identity
and supported format, then returns its existing direct `exports/` child as
an absolute `Path`. The child must be a real directory, not a symlink,
junction or other reparse point, and must resolve to itself inside the
validated project. It does not inspect unknown entries beneath `exports/`.

The method has no write, creation, deletion, site-build, editor,
credential, provider, network, HTTP or user-interface behavior. It returns
no project state or caller-selected path. The existing constructor and all
JSON, asset and public-gateway APIs stay unchanged. No new public class,
constant, alias, error type or dependency is approved. Production imports
remain standard library, Foundation validation and P1 sibling models only;
P1 must not import P4 or any later owner.

Malformed IDs, ambiguous/invalid project structure and an unsafe or absent
`exports/` child raise the existing Foundation `ValidationError` with fixed
safe wording. An absent project raises `FileNotFoundError`. Native I/O
failures remain `OSError`. Validate before returning and do not mutate
project JSON, assets, old exports or unrelated files. This call-boundary
validation is not a cross-process race or durability guarantee. The future
P4 exporter independently validates a new child destination before writing.

## Acceptance

Use only temporary P1 projects and synthetic P4 site input. Unit tests cover
created/reopened/renamed projects, canonical absolute parent, malformed,
missing and duplicated identities, corrupt metadata, missing/file/linked/
reparse export directory, linked project, native I/O failure, unrelated
children and unchanged JSON/assets. The integration test calls P1 through
its public gateway, then independently builds and exports a static site
through P4's public gateway to a new child under the returned parent. It
verifies generated bytes and no project metadata/state in the artifact.
P1 production code must not import P4.

Run Ruff, strict Pyright and all discovered Pytest tests with no skip/xfail;
review exact scope and import direction; require latest-head hosted CI
before routine merge. Produce one P1-003 report and stop for Tech Lead
review. P6-008 and UI-005 remain separate, unapproved implementation tasks;
P1-003 alone does not complete Export Folder in the browser or the Windows
MVP.
